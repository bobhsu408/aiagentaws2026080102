## 新加坡 SkillsFuture 生態系統概覽

新加坡政府建構了一個非常完整的職涯支持平台體系，包含多個互相串接的系統：

| 平台 | 功能 | 對應到你們的什麼 |
|------|------|-----------------|
| **MySkillsFuture** | 一站式入口：課程搜尋、職涯資源、自我探索工具 | 你們的整體產品定位 |
| **MyCareersFuture** | 政府驗證的職缺媒合平台 | 你們的 RAG 資料源 |
| **CareersFinder** | AI 驅動的職業推薦測驗工具 | 你們的「路徑探索」階段 |
| **Career Kaki** | AI 聊天機器人，提供個人化職涯諮詢 | 最接近你們產品的競品 |
| **Skills Framework** | 各產業的技能地圖與職業路徑圖 | 你們可以參考的底層架構 |
| **Careers & Skills Passport** | 個人技能數位護照，整合政府驗證資料 | 未來可參考的擴展方向 |

## 值得你們學習的 7 大設計思維

### 1. 政府數據的深度整合（最大亮點）

**新加坡做了什麼：**
Career Kaki 整合了 Singpass（類似台灣自然人憑證）、MyCareersFuture 職缺資料庫、MySkillsFuture 課程資料庫，以及新推出的「Careers & Skills Passport」。這讓 AI 不只是通用聊天，而是能存取使用者的就業歷史、學歷、已取得的證照來做推薦。

**你們可以學什麼：**

- 短期：在簡報中強調你們未來可以串接台灣的政府系統（台灣就業通 API、勞保投保紀錄、全國技術士資料庫）
- 中期：提出「技能護照」概念 — 使用者授權後，系統可以讀取他的勞保投保年資、投保公司、已取得的技術士證照，自動建構個人技能檔案
- 在簡報中提到這個願景，會讓評審覺得你們想得夠遠

**具體建議：** 加一頁「未來整合藍圖」：

```
台灣版 Skills Passport 構想：
├── 勞保局 → 投保歷程（自動判斷產業經歷）
├── 技術士證照系統 → 已取得證照
├── 職訓局 → 已完成的職訓課程
├── 台灣就業通 → 即時職缺與薪資行情
└── 使用者自述 → 對話中補充的軟實力與偏好
```

---

### 2. 「不只是聊天機器人」的產品定位

**新加坡做了什麼：**
GovTech 的產品經理明確表示 Career Kaki「不只是求職工具，而是全面的職涯發展平台，可以追蹤長期職涯成果，並提供洞察來影響政策決定」。

**你們可以學什麼：**

你們的論述不要停在「我們做了一個 AI chatbot」，要提升到：

> 「職涯導航家是一個**職涯健康基礎設施**，它不只解決個人當下的問題，長期而言可以：
> - 提供政府「中年轉職」群體的行為洞察（匿名化後可作為政策參考）
> - 追蹤使用者的長期職涯成果（轉職成功率、薪資變化）
> - 成為政府就業服務的數位前端，降低實體服務的負載」

---

### 3. CareersFinder 的成效數據（你們的佐證彈藥）

**新加坡的數據：**
截至 2024 年 12 月，超過 55,000 人使用了 CareersFinder 工具。數據顯示使用者在使用該工具後，申請的職業類型廣度增加了 40%。

**你們可以怎麼用：**

這是一個非常強的佐證 — 國際上已經有政府證明「AI 引導式的職涯探索工具確實能改變使用者行為」。在簡報中可以這樣引用：

> 「新加坡政府的 CareersFinder 工具已證明：AI 引導可以讓求職者探索的職業範圍擴大 40%。我們的系統不只做到這一點，更在此基礎上加入了情緒支持與階段式陪伴。」

---

### 4. Skills Framework — 結構化的技能地圖

**新加坡做了什麼：**
為超過 30 個產業建立了「Skills Framework」，每個框架包含：
- 該產業的職業地圖（Career Pathway）
- 每個職位需要的技能清單
- 技能之間的鄰近性（skills adjacency）— 用來判斷轉職可行性
- 對應的培訓課程

**你們可以學什麼：**

這是你們「可遷移技能」判斷的底層邏輯可以參考的架構。建議在技術架構中加入「技能鄰近度模型」的概念：

```
技能鄰近度模型（Skills Adjacency）

使用者現有技能 → 比對 → 目標職業所需技能 → 計算 Gap

範例：
製造業生產主管的技能組合：
├── 生產排程管理  ──→ 鄰近：專案時程管理（PM）
├── 品質管控      ──→ 鄰近：QA 工程師、稽核人員
├── 團隊管理 30 人 ──→ 鄰近：人資管理、培訓講師
├── 成本控制      ──→ 鄰近：財務分析、採購管理
└── 跨部門協調    ──→ 鄰近：業務開發、顧問業

GAP 分析：
轉 PM → 需補：敏捷方法論（1 門課，約 40 小時）
轉培訓講師 → 需補：教學技巧認證（TTTC，約 60 小時）
```

---

### 5. 分階段的使用者旅程（不是一次性互動）

**新加坡做了什麼：**
Career Kaki 被定位為長期的職涯夥伴，不是一次性工具。透過 Singpass 登入，它能記住使用者的歷程，追蹤長期發展。

**你們可以學什麼：**

在你們的產品設計中加入「使用者生命週期」的概念：

```
使用者旅程不是一條直線，而是一個循環：

第 1 次使用 → 情緒支持 + 初步探索
    ↓ （1-2 週後回來）
第 2 次使用 → 系統記得上次的對話，追問進度
    ↓ （開始行動後）
第 3 次使用 → 「你上次提到想研究 PM 的課程，進展如何？」
    ↓ （遇到困難）
第 4 次使用 → 「面試沒上沒關係，我們來看看怎麼調整」
    ↓ （成功轉職）
最後 → 「恭喜！你願意分享經驗給其他正在轉職的人嗎？」
```

---

### 6. 處理「軟性偏好」的挑戰（誠實面對限制）

**新加坡遇到的問題：**
Career Kaki 的產品經理坦承，系統目前「難以有效處理使用者的軟性需求，像是希望混合辦公、特定地點偏好、或彈性工時」。因為雇主不一定會在職缺中提供這些資訊。

**你們可以學什麼：**

在簡報中，適當地展示你們「知道系統的限制」反而加分：

> 「我們的系統目前聚焦在技能匹配與情緒支持。我們清楚知道，職涯決策涉及許多難以量化的因素（家庭、通勤、價值觀）。目前的做法是透過對話了解這些偏好，但不過度承諾精確匹配。這是我們未來持續優化的方向。」

評審會欣賞這種「知道自己不知道什麼」的成熟度。

---

### 7. 從 B2C 延伸到 B2G/B2B 的策略

**新加坡做了什麼：**
整個生態系是政府推動的，GovTech 開發 → 人力部(MOM)政策支持 → 勞動力發展局(WSG)服務落地 → 串接民間求職平台(JobStreet, FastJobs)。

**你們可以學什麼：**

在商業模式中加入「與政府協作」的路徑：

```
新加坡模式（政府主導）：
  政府出資開發 → 免費提供全民使用 → 收集數據回饋政策

台灣可行模式（公私協力）：
  我們開發核心系統 → 政府採購/合作部署
  ├── 勞動部就業服務站：作為線上前端
  ├── 各縣市就業服務處：嵌入既有服務流程
  ├── 職訓局：課程推薦引擎
  └── 地方創生計畫：協助返鄉就業媒合
```

## 你們的差異化優勢（vs. 新加坡）

看完新加坡的系統，你們不需要自卑，反而要強調你們做到了他們沒做到的事：

| 面向 | 新加坡 Career Kaki | 你們的職涯導航家 |
|------|-------------------|-----------------|
| 情緒支持 | ❌ 沒有，純功能性 | ✅ 核心特色，情緒優先設計 |
| 對話階段管理 | ❌ 無結構，自由聊 | ✅ 四階段有目的的引導 |
| 中年族群專注 | △ 通用，非特定族群 | ✅ 專為 35-55 歲設計 |
| 心理學理論基礎 | ❌ 無 | ✅ SFBT、認知情緒雙路徑 |
| 政府數據整合 | ✅✅ 非常完整 | △ 願景階段（但有規劃） |
| 技能護照 | ✅ 已實作 | 可作為 Phase 2 目標 |

**你們在簡報中的定位：**

> 「新加坡的 Career Kaki 證明了 AI 職涯引導的可行性與價值。但他們是『功能導向』的通用工具。我們是『以人為本』的深度陪伴系統 — 專注在最需要幫助的中年轉職族群，先處理情緒、再解決問題。這是台灣社會特別需要的溫度。」
